## 结论

原版 99 项测试确实全部通过，但不能据此判定授权、预算和记录完整性已经可靠。首批新增的 9 个行为回归用例在原版上全部失败。修复后新增 23 项回归，连同原有用例共 122 项通过。原有 confirm 用例原本直接断言「调用成功」，没有提供确认服务，也没有检查是否询问过用户；现已改为实际模拟允许，并断言询问次数。

本分支是修复候选，不是新的正式发布；没有更新 main 或移动 v0.2.1 标签。完整桌面宿主验收仍待执行。

## 发现及处理

| 优先级 | 触发场景与原有结果 | 本次处理 |
| --- | --- | --- |
| P1 | 同一会话两次咨询交错结束，各自将旧历史快照写回，可能丢记录、恢复旧运行状态或覆盖核验标注 | `openHistory` 每次读取/修改前刷新最新文件，同一运行时内同步更新 |
| P1 | 用户清空历史后，仍在运行的咨询结束，旧快照把已删除记录写回来 | patch 不恢复已删除的 ID；准备期间被清空的咨询不会再发出请求 |
| P1 | 会话预算按可见历史条数计算，已处理记录轮转后额度被释放，清空也重置额度 | 独立持久化累计计数，轮转/清空保留计数；模型工具路径也预约同一会话额度，未获同意则退款 |
| P1 | confirm 模式仍保留默认 plan 预授权，不询问用户就付费调用 | 宿主提供可信的每次调用策略，confirm 强制经过确认；默认确认窗口从 250ms 调整为 60s |
| P1 | 自动模式遇到 general 等非默认 focus 仍被拒绝或因缺确认服务抛错 | 自动模式覆盖受支持 focus；设置驱动的工具声明全部 focus，由实时策略决定是否可用 |
| P1 | 模型侧工具固定使用挂载时的模型与输出上限，忽略设置页更新 | 每次调用读取当前模型选择与高级配置；确认等待结束后再次核对开关、模式与目标 |
| P1 | 用户预览后材料变化，开始时重新收集并直接发送；客户端也可跳过预览 | 客户端先预览再确认，发送 expectedDigest / expectedTarget；服务端变化即拒绝，不调用模型 |
| P1 | 准备材料期间取消，仍执行 llm.stream；diff 不响应时无限等待 | 准备与预览均设置本地等待上限；取消/超时/关闭在调用前终止，并释放槽位 |
| P2 | 持久化 normalizeRecord 丢弃材料摘要、截断/旧轮次警告、材料 digest 等字段 | 保留这些已产生的事实，使重开卡片后仍能解释材料范围 |
| P2 | NO_ADVICE 字符串被当作实际意见，显示待核验并阻止历史轮转 | 状态保留 no_advice，意见正文为空；读取旧记录也不把该标记当作待办 |
| P2 | 缓存中的会话授权不会在 24 小时后自动失效 | effectiveMode 在实际使用时检查授权时间 |
| P1 | 固定模型选择不完整时自动退回会话模型，可能使用用户没选的供应商 | 保留未完成选择，报告缺少模型，等待补齐 |
| P2 | 适配器响应 abort 时抛错，取消被归类成一般失败 | 本地取消已发生时保持取消终态，清理监听器和宽限计时器 |
| P2 | 向主力交付返回 Promise 时，未等待就标已交付；异步拒绝可能未处理 | 等待交付方法完成，错误返回给调用方，未成功不标已交付 |
| P2 | 连接检查只 abort 信号，忽略 abort 的适配器使界面永久等待 | 与本地截止时间竞争；无完整结果不会报连接成功，保留供应商原始失败信息 |

具体行为回归见 `tests/review-regressions.test.mjs`。模型侧确认回归见 `tests/tool-gate.test.mjs`。

## 升级行为变化

1. `consult.start` RPC 需要先调用 `materials.preview`，带回其 `digest` 与 `target` 为 `request.expectedDigest` / `request.expectedTarget`。旧客户端需与服务端一起更新。内部 `createConsultService.start` 仍可由受信任宿主直接调用。
2. 清空历史只删除记录，不清零会话咨询额度。需要继续咨询时，用户在高级设置提高上限或设为 0。
3. 旧文件没有累计计数时，只能以尚存的非拒绝记录为迁移起点。已在旧版被轮转/清空的历史次数无法恢复，不能宣称已重建完整历史账目。
4. 准备阶段失败/取消仍按既有「非拒绝尝试」计数保守占用额度；该值不是供应商账单或 HTTP 请求次数。独立的连接检查不计入会话咨询额度。
5. 持久化的同步读改写修复同一 Node 宿主内的交错，不提供跨进程锁。两个进程同时写同一个 profile 仍不在本次保证范围内。

## 合并前桌面验收

- 从干净 profile 安装修复分支，确认设置页/会话入口/状态面板正常挂载。
- confirm + plan：拒绝时真实调用为 0；明确允许时仅发出一次。等待确认时关闭插件，再允许，仍不能调用。
- 先预览后更改主对话方案：确认开始应提示材料变化；重新预览再确认才能调用。修改顾问模型也应要求重新确认。
- 同时发起两次咨询，让后发者先返回，再核验任意记录；所有结果/标注均应保留。运行期间清空后不能恢复旧记录。
- 提高会话次数至超过历史保留条数，验证上限仍有效；交替使用模型工具和手动按钮也不能绕过。
- 模型下拉切换到固定供应商/模型，确认模型侧工具与手动咨询实际使用的目标一致。
- 验证正常交付、异步交付失败、取消、连接检查超时、NO_ADVICE 不增加待核验计数。

## 后续产品工作

- 模型工具的详细账本/工具结果与手动咨询的历史卡片仍是两条记录路径；本次统一的是授权、模型选择和会话预算，不宣称已统一所有历史和核验交互。
- 手动咨询的并发上限 3 仍由 consult service 管理；它不是模型工具与连接检查共用的全局并发限制。
- 跟随会话模型目前依赖宿主 `agentDefaultModel.currentSelection()`；多会话并行时是否等同每个会话的模型，需核对真实宿主接口。
- 用户点击核验按钮属于人工标注，不能替代主力核验结果的自动关联与证据回写。
- 正式布局/键盘操作/多窗口同步的验收，应在真实宿主执行；本轮没有把静态截图当作运行测试。
